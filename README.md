ระบบนี้ไม่มีค่าใช้จ่าย ทำงานผ่านหน้าเว็บทั้งหมด ไม่ต้องติดตั้งโปรแกรม

## วิธีทำงาน (แบ่งหน้าที่)

| ใคร | ทำอะไร | ต้องมีบัญชี GitHub ไหม |
|---|---|---|
| **แอดมิน / การตลาด** (1–2 คน) | แปลง PDF ใน Studio แล้วอัปโหลดขึ้น GitHub **ครั้งเดียวต่อโครงการ** และอัปโหลดทับเมื่อข้อมูลเปลี่ยน | ต้องมี |
| **ทีมขาย** | เปิดหน้า **คลัง Sale Kit** แล้วกด "ส่งทาง LINE" หรือ "คัดลอกลิงก์" ส่งลูกค้า | ไม่ต้องมี |
| **ลูกค้า** | กดลิงก์ในแชต แล้วเปิดเป็นหนังสือพลิกหน้าได้ทันที | ไม่ต้องมี |

ลิงก์สำคัญ (เปลี่ยน `ชื่อบัญชี` เป็นของจริง):

- ลิงก์ของแต่ละเล่ม: `https://ชื่อบัญชี.github.io/flipbook/verano-park-salekit.html`

### หลักการตั้งชื่อลิงก์ (ตกลงกันครั้งเดียว แล้วใช้ตลอด)
- รูปแบบ: `ชื่อโครงการ-ประเภทเอกสาร` เช่น `verano-park-salekit`, `awasada-price-list`
- **ไม่ต้องใส่วันที่หรือเลขเวอร์ชันในชื่อ** เมื่อข้อมูลเปลี่ยน ให้อัปโหลดทับด้วยชื่อเดิม ลิงก์ที่ทีมขายและลูกค้ามีอยู่จะแสดงเวอร์ชันใหม่เอง
- ตั้งชื่อหนังสือ (ภาษาไทยได้) ให้ชัดเจน เพราะชื่อนี้จะแสดงในคลัง Sale Kit และเวลาแชร์ใน LINE

## ส่วนที่ 1: ตั้งค่าครั้งแรก (ประมาณ 10 นาที)

### 1. สมัคร GitHub
- สมัครที่ **github.com/signup** (ฟรี)
- **ชื่อบัญชีจะปรากฏในลิงก์ทุกลิงก์** เช่น ชื่อบัญชี `wonderhouse` จะได้ลิงก์ `wonderhouse.github.io` จึงควรตั้งชื่อที่สื่อถึงบริษัท
- ถ้าจะใช้กันหลายคน แนะนำให้สร้าง **Organization** ในชื่อบริษัท (ฟรี): กดรูปโปรไฟล์ → Your organizations → New organization → เลือก Free

### 2. สร้าง repo สำหรับเก็บหนังสือ
1. กดปุ่ม **+** มุมขวาบน → **New repository**
2. **Owner:** เลือกบัญชีหรือ Organization ของบริษัท
3. **Repository name:** `flipbook` (ชื่อนี้จะอยู่ในลิงก์ด้วย)
4. เลือก **Public** (แพ็กเกจฟรีใช้ GitHub Pages ได้เฉพาะ repo สาธารณะ)
5. ติ๊ก **Add a README file**
6. กด **Create repository**

### 3. อัปโหลดหน้า Studio และหน้าคลัง Sale Kit
1. ในหน้า repo กด **Add file → Upload files**
2. ลากไฟล์ **`index.html`** และ **`kits.html`** จากชุดนี้ไปวางพร้อมกัน
3. เลื่อนลงไปด้านล่าง แล้วกด **Commit changes**

### 4. เปิดใช้ GitHub Pages
1. ในหน้า repo กด **Settings** (แท็บด้านบน) → เมนูซ้าย **Pages**
2. ในส่วน **Build and deployment**:
   - **Source:** `Deploy from a branch`
   - **Branch:** `main` และโฟลเดอร์ `/ (root)` → กด **Save**
3. รอ 1–2 นาทีแล้วรีเฟรชหน้า จะเห็นข้อความ **"Your site is live at https://ชื่อบัญชี.github.io/flipbook/"**

### 5. เปิด Studio และบันทึกเป็นบุ๊กมาร์ก
- เปิดลิงก์จากข้อ 4 จะเห็นหน้า Flipbook Studio พร้อมหนังสือตัวอย่าง
- ช่อง **"ที่อยู่เว็บ GitHub Pages"** จะถูกเติมให้อัตโนมัติ
- บันทึกหน้านี้เป็นบุ๊กมาร์กไว้ ทีมขายใช้หน้านี้หน้าเดียว

### 6. แจกหน้าคลัง Sale Kit ให้ทีมขาย
- ส่งลิงก์ `https://ชื่อบัญชี.github.io/flipbook/kits.html` เข้ากลุ่ม LINE ของทีมขาย แล้ว**ปักหมุด**ไว้
- แนะนำให้ทีมขายเพิ่มหน้านี้ไว้บนหน้าจอโฮมของมือถือ
  - iPhone: เปิดลิงก์ใน Safari → ปุ่มแชร์ → **Add to Home Screen**
  - Android: เปิดลิงก์ใน Chrome → เมนู ⋮ → **Add to Home screen**
- หน้านี้ดึงรายชื่อหนังสือจาก repo อัตโนมัติ เมื่อแอดมินอัปโหลดเล่มใหม่ ทีมขายจะเห็นในหน้านี้เอง (ถ้ายังไม่ขึ้น ให้รีเฟรชหน้า)

### 7. เพิ่มแอดมินคนอื่นที่จะอัปโหลดหนังสือ (ถ้ามี)
- สมาชิกแต่ละคนต้องสมัคร GitHub ของตัวเอง
- ถ้าเป็น repo ส่วนตัว: **Settings → Collaborators → Add people** แล้วใส่ชื่อบัญชีหรืออีเมล
- ถ้าเป็น Organization: เชิญเข้า Organization แล้วให้สิทธิ์ **Write** กับ repo `flipbook`
- คนที่แค่เปิดดูหนังสือ (รวมถึงลูกค้า) **ไม่ต้องมีบัญชี GitHub**

## ส่วนที่ 2 (แอดมิน): สร้างหนังสือเล่มใหม่ (ครั้งเดียวต่อโครงการ ประมาณ 3 นาที)

1. เปิด Studio จากบุ๊กมาร์ก
2. **เลือกไฟล์ PDF** หรือลากไฟล์มาวาง
3. ตรวจสองช่องนี้:
   - **ชื่อหนังสือ:** ใช้ภาษาไทยได้ ชื่อนี้จะแสดงเป็นหัวเรื่องเวลาแชร์ใน LINE
   - **ชื่อลิงก์:** ใช้ได้เฉพาะ a–z, 0–9 และ - เช่น `verano-park-salekit` ถ้าชื่อหนังสือเป็นภาษาไทยล้วน ระบบจะตั้งเป็น `book-ปีเดือนวัน` ให้ แนะนำให้พิมพ์ชื่อที่อ่านง่ายแทน
4. กด **บันทึกไฟล์หนังสือ (.html)** เครื่องจะดาวน์โหลดไฟล์ เช่น `verano-park-salekit.html`
5. กดปุ่ม **อัปโหลดที่ GitHub** ที่ขึ้นมาในกรอบสีฟ้า หน้าอัปโหลดของ repo จะเปิดขึ้น
6. ลากไฟล์ที่เพิ่งดาวน์โหลดไปวาง แล้วกด **Commit changes**
7. รอประมาณ 1 นาที ดูสถานะได้ที่แท็บ **Actions** ของ repo ถ้าขึ้นเครื่องหมายถูกสีเขียวแปลว่าพร้อมแล้ว
8. **ตรวจก่อนแจ้งทีม:** เปิดลิงก์ในหน้าต่างไม่ระบุตัวตน (Ctrl+Shift+N) และลองส่งเข้า LINE ของตัวเองแล้วเปิดบนมือถือ ถ้าขึ้น 404 ให้รออีกสักครู่
9. แจ้งในกลุ่มทีมขายว่ามี Sale Kit ใหม่ เล่มนี้จะขึ้นในหน้าคลัง Sale Kit แล้ว

## ส่วนที่ 2.1 (ทีมขาย): ส่ง Sale Kit ให้ลูกค้า (10 วินาที)
1. เปิดหน้า **คลัง Sale Kit**
2. พิมพ์ค้นหาชื่อโครงการ
3. กด **ส่งทาง LINE** แล้วเลือกแชตของลูกค้า หรือกด **คัดลอกลิงก์** แล้วนำไปวางในแชต
4. ถ้าลูกค้าต้องการไฟล์ไว้สั่งพิมพ์ ให้ส่งไฟล์ PDF ต้นฉบับไปด้วย

## ส่วนที่ 3: แก้ไขหรือลบหนังสือ

### แก้ไข (เช่น ราคาเปลี่ยน) โดยใช้ลิงก์เดิม
- สร้างหนังสือใหม่ใน Studio โดยใช้ **ชื่อลิงก์เดิม** แล้วอัปโหลดทับ GitHub จะแทนที่ไฟล์เดิม
- ลิงก์เดิมจะแสดงเวอร์ชันใหม่ภายในไม่กี่นาที ลูกค้าบางคนอาจยังเห็นเวอร์ชันเก่าอยู่ไม่เกินประมาณ 10 นาที เพราะเบราว์เซอร์เก็บแคชไว้

### ลบ
1. ในหน้า repo คลิกชื่อไฟล์ที่ต้องการลบ
2. กดปุ่ม **⋯** มุมขวาบน → **Delete file** → **Commit changes**
3. ภายในไม่กี่นาที ลิงก์นั้นจะขึ้น 404

⚠️ **ข้อควรรู้:** repo เป็นสาธารณะ **คนภายนอกเห็นรายชื่อไฟล์ทุกเล่ม** และหลังจากลบแล้ว **ไฟล์เก่ายังเปิดดูได้จากประวัติ (History) ของ repo** ห้ามใส่ข้อมูลลับหรือข้อมูลลูกค้าในหนังสือ ใส่เฉพาะเอกสารที่ตั้งใจเผยแพร่อยู่แล้ว

## ส่วนที่ 4 (ทางเลือก): ใช้โดเมนของบริษัท
ทำให้ลิงก์เป็น `https://book.wonderhouse.co.th/verano-park-salekit.html`
1. repo → **Settings → Pages → Custom domain** → ใส่ `book.wonderhouse.co.th` → **Save**
2. ที่ผู้ให้บริการ DNS ของโดเมน เพิ่มระเบียน **CNAME** ชื่อ `book` ชี้ไปที่ `ชื่อบัญชี.github.io`
3. รอจน GitHub ตรวจผ่าน แล้วติ๊ก **Enforce HTTPS**
4. เปลี่ยนบุ๊กมาร์กไปที่ `https://book.wonderhouse.co.th/` ช่องที่อยู่เว็บใน Studio จะเปลี่ยนตามเอง แต่ปุ่ม "อัปโหลดที่ GitHub" จะไม่ขึ้นแล้ว ให้บุ๊กมาร์กหน้า repo ไว้แทน

## ข้อจำกัด

| เรื่อง | ขีดจำกัด | ผลในทางปฏิบัติ |
|---|---|---|
| ขนาดไฟล์ต่อเล่ม | ไม่เกิน 25 MB เมื่ออัปโหลดผ่านหน้าเว็บ | Studio จะเตือนเมื่อไฟล์ใหญ่เกิน หนังสือ 20 หน้าที่ความคมชัดมาตรฐานมีขนาดประมาณ 2–6 MB |
| ขนาดเว็บทั้งหมด | ไม่เกิน 1 GB | เก็บได้ประมาณ 150–300 เล่ม ควรลบเล่มที่เลิกใช้แล้ว |
| ปริมาณการเข้าชม | soft limit 100 GB ต่อเดือน | ถ้าหนังสือเล่มละ 5 MB เปิดได้ประมาณ 20,000 ครั้งต่อเดือน |
| ความเป็นส่วนตัว | repo เป็นสาธารณะ | ระบบใส่ `noindex` ในไฟล์หนังสือแล้ว Google จะไม่นำไปแสดงในผลค้นหา แต่ใครที่เข้า repo ก็ยังเห็นไฟล์ |
| ภาพตัวอย่างเวลาแชร์ใน LINE | แสดงชื่อหนังสือและจำนวนหน้า | ยังไม่มีภาพหน้าปก |
| เงื่อนไขการใช้งานของ GitHub | GitHub Pages ไม่อนุญาตให้ใช้เป็นโฮสต์สำหรับเว็บที่มุ่งเน้นการทำธุรกรรมเชิงพาณิชย์ | เอกสารการตลาดอยู่ในพื้นที่สีเทา ถ้าการใช้งานขยายใหญ่ขึ้น ควรย้ายไปใช้ระบบ Cloudflare ที่เตรียมไว้ |
